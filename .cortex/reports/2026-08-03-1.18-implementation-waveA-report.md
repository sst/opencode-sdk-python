2. `_models.py` `model_dump_json`/`model_dump` overrides mismatch installed pydantic: `_models.py` byte-identical from `main` through `HEAD`; identical 2 errors at baseline. Root cause: pydantic drift - `uv.lock` and the venv have pydantic **2.13.4**, `requirements-dev.lock` pins **2.10.3**, the overrides target the older signature (2.13 added `fallback`/`polymorphic_serialization` params). Wave A did not change dependency versions (uvlock worker proved the 43-package surface identical) or `_models.py`.

Note: mypy also analyzed `_files.py` when run from the worktree (10 vs 2 errors) - `mypy.ini` excludes `_files.py` by design ("it's fine to just use Pyright"); the exclusion did not apply from the worktree location. Artifact of the baseline setup, not a wave change.
