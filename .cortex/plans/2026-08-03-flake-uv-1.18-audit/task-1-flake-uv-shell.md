# Task 1: flake.nix (dev toolchain) + uv sync verification

## Context

This repo is the Walzen Group fork of the Stainless-generated opencode Python
SDK (`opencode-ai-wg`, imports as `opencode_ai`). It has `uv.lock` and a
`pyproject.toml` that still carries rye-era config (`[tool.rye] managed = true`).
The user wants a reproducible dev environment: a pinned `flake.nix` whose
devShell provides the dev toolchain, with uv as the package tool left as-is.
Nix 2.35.1 is installed on this host. The `.cortex` tree (plans/memory) exists.

## Target

- `/workspaces/opencode-sdk-python/flake.nix` (new)
- `/workspaces/opencode-sdk-python/flake.lock` (generated by `nix flake lock`)
- `.venv/` at repo root (created by uv; already gitignored)

Non-goals: do not touch `pyproject.toml`, `uv.lock`, `requirements*.lock`,
`.python-version`, `src/`, `docs/`, `spec/`, `.stats.yml`. Do not run `uv init`,
do not edit `.gitignore`. Do not commit anything.

## Change

1. Write `flake.nix` with:
   - `inputs.nixpkgs.url = "github:NixOS/nixpkgs/<pin>"` where `<pin>` is a
     **fixed rev** of a current stable branch (as of 2026-08-03, a stable branch
     released in 2025 or 2026; if you cannot confirm which stable branch exists,
     pin `nixpkgs-unstable` at a fixed rev and say which you chose and why).
     The point is reproducibility: `flake.lock` records the exact input.
   - `outputs` for at least `x86_64-linux` and `aarch64-darwin` (maintainers
     work on both).
   - `devShells.default` providing, via `pkgs.mkShell` or equivalent:
     `python3` (a 3.12 or 3.13), `uv`, `ruff`, `mypy`, `pyright`, and
     `nodejs` (22.x) - node is needed because the repo's prism mock server runs
     via `npm exec --package=@stainless-api/prism-cli ...` (see
     `scripts/mock`).
   - No `shellHook` that mutates the repo. A comment or a version-echo hook is
     fine.
   - Keep it boring and small: no overlays, no flake-utils dependency unless it
     genuinely simplifies the systems list.
2. Run `nix flake lock` at the repo root (creates `flake.lock`; if `nix develop`
   needs network to fetch the input, that is expected).
3. Run `nix flake check` - must exit 0.
4. Enter the shell and run the Acceptance gates. Note: the venv interpreter is
   governed by `.python-version` (3.9.18); uv will fetch its own managed Python
   for that pin. That is expected and fine.

## Constraints (from plan index)

- Repo root: `/workspaces/opencode-sdk-python`. All paths absolute.
- Do NOT commit. Leave `flake.nix`/`flake.lock` untracked.
- Do NOT modify `pyproject.toml`, `uv.lock`, `requirements*.lock`,
  `.python-version`, `src/`, `docs/`, `spec/`, `.stats.yml`.
- Artifacts under `.cortex/plans/2026-08-03-flake-uv-1.18-audit/`, never `/tmp`.

  them alone.
- User-facing writing: i-have-adhd convention (lead with the answer, three lines
  or fewer, cut filler).

## Acceptance

Run every gate inside the pinned shell (`nix develop --command <cmd>`), from the
repo root:

1. `nix flake check` - exit 0.
2. `nix develop --command bash -c 'uv --version && python --version && ruff --version && mypy --version && pyright --version && node --version'` -
   every tool prints a version, exit 0.
3. `nix develop --command uv lock --check` - if it reports the lockfile stale,
   do NOT edit it; capture the output and report it in your hand-back.
4. `nix develop --command uv sync --frozen` - exit 0, creates `.venv`.
5. `nix develop --command uv run python -c "import opencode_ai"` - exit 0
   (proves the package imports from the uv venv).

If a gate cannot pass (e.g. uv cannot fetch the pinned interpreter, network
blocks the nixpkgs fetch), STOP and report the blocker with the exact output;
acceptance criteria are not descoped.

## Report format

A diff, not a commit: files created, `git diff --stat` (or `git status --short`
showing the new files), gate output for each of the five gates, any deviations.
Note which nixpkgs pin you chose and why. Changes stay uncommitted.
